# ブックマークレットで記事を追加する

iPhoneのSafariやPCのブラウザで見ている記事を、xangi-feedへ送れます。受け取り画面で「記事を追加」「追加してNotion保存」を選びます。Notion保存は、既存の保存AI・利用者の保存スキルに従います。

## 最初の登録

xangi-feedの「設定」→「ブックマークレット」を開きます。設定内にこの接続先専用のコードとコピーボタンを表示します。「詳しい登録手順・受け取り画面」からiPhone向けの手順も確認できます。

### iPhoneのSafari

1. 設定内の「詳しい登録手順・受け取り画面」を開き、Safariの通常のブックマークへ追加します。
2. 画面の「コードをコピー」を押します。
3. Safariのブックマーク一覧を編集し、追加したブックマークのURL欄をコピーしたコードに置き換えて保存します。
4. 記事をSafariで開き、そのブックマークを選びます。

ホーム画面アイコンではなく、Safariのブックマークへ登録します。アドレスバーへの貼り付けではなく、ブックマークのURL編集欄を使います。iPhone実機での登録・実行は未確認です。

### PC

受け取り画面の「xangi-feedに送る」をブックマークバーへドラッグします。ドラッグできなければ、通常のブックマークを作成し、URL欄へ登録用コードを貼り付けます。

## 記事を送る

記事やYouTubeのページで登録したブックマークを実行します。同じタブでxangi-feedの受け取り画面を開き、URLとタイトルを確認できます。

- **記事を追加**: URLとタイトルを登録します。既存URLは重複登録せず既存記事を使います。
- **追加してNotion保存**: 記事追加後、既存の保存AIへ依頼します。PDF・音源・動画・文字起こしの取得やDBへの保存は利用者の保存スキルが担当します。
- **状態を確認**: 実際の保存結果を取得します。依頼中・一部保存・回答待ち・結果不明・完了を区別します。処理中は表示中の画面で約5秒ごとにも確認します。

ページを開いただけでは登録もNotion保存も実行しません。APIキーやNotionキーは登録コードに含めません。同じブラウザでxangiへログインして使います。接続先が変わった場合は、新しい接続先の受け取り画面でコードを登録し直します。

## 読み込み直した場合

URL・タイトルと直近の依頼IDは、そのタブのsessionStorageに保持します。再読み込み後も状態確認できます。保存依頼中に画面を閉じた場合は、結果不明として既存の依頼を照会します。無条件に再送しません。保存AIの未設定など、APIが明示的に拒否した場合は、設定を直してから利用者の操作で再依頼できます。

新しくブックマークレットから記事を受け取ると、前の入力を置き換えます。元の記事や依頼はxangi-feed側に残ります。タブを完全に閉じた場合やプライベートブラウズの制限で進捗を保持できない場合は、xangi-feedか保存AIの会話で確認してください。

## 動かない場合

サイトのCSPやブラウザの制限でブックマークレットが実行できないことがあります。その場合は受け取り画面を直接開き、記事URLを貼り付けて同じ追加・保存操作ができます。Safari以外のアプリ内ブラウザでは、Safariで記事を開き直してください。

ログインを求められた場合は、同じブラウザでxangiへログインし、記事側でブックマークレットをもう一度実行します。ブックマークレットはURLとタイトルを渡すだけで、閲覧中ページからxangiのAPIへ直接通信しません。記事情報はURLフラグメントで渡し、受け取り後にアドレスから消します。

## 開発・検証

`./scripts/check` は既存テスト・JS構文・ブックマークレットのNodeテストを実行します。

```sh
uv run --offline --with playwright python tests/bookmarklet_browser.py /tmp/feed-bookmarklet-check
```

OSライブラリ不足でWebKitを起動できない環境では `--engine chromium` でChromiumだけを検証でき、WebKitは未確認として扱います。

Chromium（PC幅・iPhone幅）とWebKit（iPhone幅）で、実際のjavascript URLの実行、確認前の書込みなし、追加・保存依頼、再読み込み、重複抑止、保存結果・通信結果不明からの復旧を検証します。DBは一時領域、保存AIはモックです。WebKitの幅指定試験はiPhone実機での確認とは別です。

外部記事からはxangiの正規UI入口を経由して受け取り画面へ移動します。サービスURLへの直接遷移を拒否する保護は維持します。
